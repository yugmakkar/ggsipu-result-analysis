GGSIPU Result Analysis & CGPA Calculator

Problem Statement 22 · System architecture, ER diagram and data flow diagrams · Stack: Java + MySQL on Linux, with Apache PDFBox as the only non-core library.

0. Two-semester plan

Semester 1: Core engine (Java + SQL)

  • MySQL schema (all tables in the ERD below), created with SQL scripts
  • Reading a GGSIPU result PDF with Apache PDFBox, then extracting enrollment no., name, paper IDs and marks with Java regex
  • Saving the data through JDBC (DAO classes, PreparedStatement, transactions)
  • Converting marks to a grade and grade point, then calculating SGPA (Sem I, Sem II) and CGPA
  • A menu-driven console / Swing UI: import PDF, search a student, show the marksheet
  • Runs on Linux. A shell script batch-imports a folder of PDFs

Semester 2: Web app + analytics

  • Web front-end with Servlets + JSP on Apache Tomcat (HTTP client–server, see CN)
  • Admin page to upload PDFs (multipart POST). Student page to check results
  • Topper analysis: subject-wise, college-wise, semester-wise and overall university topper
  • Ranking with SQL window functions and with Java Comparator sorting
  • Parallel parsing of many PDFs with a thread pool (ExecutorService, see OS)
  • Deployment on an Ubuntu server, with a cron job that backs up the database

1. System architecture (3-tier)

The browser (or the Sem 1 desktop UI) sends requests. Java code on Tomcat does all of the parsing and calculation. MySQL stores the structured data, and the Linux file system stores the original PDFs.

4. Topper queries (DBMS)

-- CGPA view
CREATE VIEW v_cgpa AS
SELECT enrollment_no, ROUND(SUM(credit_points) / SUM(total_credits), 2) AS cgpa
FROM semester_result GROUP BY enrollment_no;

-- Subject-wise topper
SELECT * FROM (
  SELECT m.paper_id, s.name, m.total_marks,
         RANK() OVER (PARTITION BY m.paper_id ORDER BY m.total_marks DESC) AS rnk
  FROM marks m JOIN student s ON s.enrollment_no = m.enrollment_no
) t WHERE rnk = 1;

-- Semester-wise topper:  PARTITION BY r.semester        ORDER BY r.sgpa DESC  (on semester_result)
-- College-wise topper:   PARTITION BY s.college_code    ORDER BY c.cgpa DESC  (on v_cgpa JOIN student)
-- Overall topper:        no partition                   ORDER BY c.cgpa DESC  (RANK keeps ties)
